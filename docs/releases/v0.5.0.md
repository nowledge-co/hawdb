# HawDB v0.5.0

HawDB is an embedded Rust database library. This release builds on
[v0.4.0](https://github.com/nowledge-co/hawdb/releases/tag/v0.4.0).

## Highlights

- PageRank and Louvain can stream canonical adjacency when a resident projection
  exceeds its memory budget. The Rust facade can prepare complete results and
  atomically publish node properties with source/publication epochs and freshness
  status. Preparation, retained staging and publication respect caller and host
  resource admission. Ordinary algorithm queries remain read-only.
  ([#905](https://github.com/nowledge-co/hawdb/pull/905),
  [#909](https://github.com/nowledge-co/hawdb/pull/909))
- Mem graph procedures preserve projection relationship predicates, PageRank
  options and Louvain phase/level semantics across resident and streaming
  execution. Identity hydration reads selected columns under admission rather
  than copying complete records.
  ([#903](https://github.com/nowledge-co/hawdb/pull/903))
- Context-aware bounded snapshots carry caller cancellation, deadlines and
  resource reservations into the embedded runtime. Profiled Cypher reads return
  rows and execution evidence from the same immutable snapshot.
  ([#907](https://github.com/nowledge-co/hawdb/pull/907),
  [#908](https://github.com/nowledge-co/hawdb/pull/908))
- Incremental search projection maintenance publishes target-bound mutation
  segments and compacts bounded overlapping ranges. Typed Rust entrypoints expose
  changefeed catch-up and host-scheduled maintenance while retaining pinned
  readers and publication conflict checks.
  ([#900](https://github.com/nowledge-co/hawdb/pull/900))
- Zstd contexts and workspaces use the host Rust allocator on native and browser
  WASM builds. HawDB adds no allocator backend; the host registers its choice in
  the final binary or WASM module.
  ([#958](https://github.com/nowledge-co/hawdb/pull/958),
  [allocator contract](../ALLOCATORS.md))

## Correctness and development

- Cypher preserves optional bindings and MATCH constraints, and validates bounded
  MATCH before resolving types or reading input.
  ([#895](https://github.com/nowledge-co/hawdb/pull/895),
  [#899](https://github.com/nowledge-co/hawdb/pull/899),
  [#901](https://github.com/nowledge-co/hawdb/pull/901))
- Lexical pruning respects block-bound validity; permanent cleanup failures
  isolate retained capacity and progress by root. Reused branch names resolve to
  their current owners, and strict-append EXPLAIN reports enforce budgets.
  ([#906](https://github.com/nowledge-co/hawdb/pull/906),
  [#893](https://github.com/nowledge-co/hawdb/pull/893),
  [#920](https://github.com/nowledge-co/hawdb/pull/920),
  [#887](https://github.com/nowledge-co/hawdb/pull/887))
- Optimizer rule families have clearer ownership and narrower consumer
  dependencies. Root tests are partitioned, and streamed document lifecycle tests
  use dedicated optimized test libraries with assertions and overflow checks
  retained. This build optimization does not change production compilation.
  ([#874](https://github.com/nowledge-co/hawdb/pull/874),
  [#910](https://github.com/nowledge-co/hawdb/pull/910),
  [#965](https://github.com/nowledge-co/hawdb/pull/965))

## Compatibility and qualification

- Select `hawdb = "0.5.0"` for the Rust facade. Workspace packages, versioned
  internal dependencies, the Python source binding and explicit Bazel version
  metadata are aligned. The Rust toolchain remains pinned at 1.97.1. Python is
  still a source binding; this preparation does not publish it to PyPI.
- PageRank procedure calls follow the pinned Mem/Ladybug contract: iteration
  caps 0 and 1 return the initial state, and cap 2 performs one update. Procedure
  normalization and dangling-node behavior differ from the legacy typed helper.
  Legacy `PageRankOptions` and `LouvainOptions` struct literals remain supported;
  explicit procedure option types expose the extended contract. Louvain
  `maxPhases` returns a final assignment per original node, while `maxLevels`
  retains hierarchy output.
- Hosts using lower-level crates should review the optimizer crate split and
  graph procedure plan changes. `hawdb` remains the supported host facade;
  internal crate versions do not establish independent integration contracts.
- Streaming analytics still requires admitted node state, complete staging and
  a single publication transaction. Retain the prepared object for idempotent
  retries; serialized job resumption is not provided. Readers of published
  properties must filter by the current publication ID. Representative Mem
  workload qualification remains open in
  [#294](https://github.com/nowledge-co/hawdb/issues/294) and
  [#898](https://github.com/nowledge-co/hawdb/issues/898).
- Incremental search maintenance does not complete the full scale, initial
  ownership/reclamation or power-loss acceptance of
  [#291](https://github.com/nowledge-co/hawdb/issues/291). Branch reclamation and
  platform power-loss qualification also remain tracked in
  [#778](https://github.com/nowledge-co/hawdb/issues/778) and
  [#820](https://github.com/nowledge-co/hawdb/issues/820).
- Historical pre-1.0 Zstd frames now fail explicitly. Modern compressed payload
  bytes and WAL/checkpoint/envelope versions are unchanged by the allocator
  bridge. Static Zstd linkage is required; dependency upgrades must requalify its
  private custom-memory ABI.
- This release does not authorize HawDB in stable or GA Mem artifacts, or
  establish full production replacement readiness. The development/nightly,
  complete import and full-data verification rules in [AGENTS.md](../../AGENTS.md)
  still apply. See the open
  [production-readiness tracker](https://github.com/nowledge-co/hawdb/issues/846)
  for remaining host qualification.

## Publication procedure

After the preparation PR lands and the selected main revision passes release
checks, publish the 40 publishable workspace packages in dependency order using
the existing script:

```console
bash scripts/publish-crates.sh --print-order
bash scripts/publish-crates.sh -- --locked
```

The publisher skips the fuzz and qualification tools and can resume a failed run
with `--from CRATE`. A registry dry run of a dependent crate requires its matching
dependencies to exist in the registry; it cannot validate an entirely unpublished
version by itself. Record the exact published commit before creating the
`v0.5.0` tag and GitHub release. Registry uploads, tag creation and public release
publication are separate from this preparation change.

[Full change history](https://github.com/nowledge-co/hawdb/compare/v0.4.0...v0.5.0).
