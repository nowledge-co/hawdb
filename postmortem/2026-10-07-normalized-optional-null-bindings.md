# Normalized OPTIONAL bindings lost NULL identity

Owner: https://github.com/nowledge-co/hawdb/issues/892.
Discovered while integrating https://github.com/nowledge-co/hawdb/issues/293 with default parser delivery https://github.com/nowledge-co/hawdb/pull/868 and https://github.com/nowledge-co/hawdb/issues/158.

## Runtime failure and cause

On main `04a8299733ef83e55d800c628f9711ab1e257a7d`, a synthetic isolated seed followed by OPTIONAL then required traversal produced neighbors of the legitimate stored node 0. The normalized operator wrote an empty `NodeRecord(NodeId(0))`; subsequent Expand or GraphMatch used its valid id. Unknown relationship types also returned before OPTIONAL consumed upstream input, losing required NULL rows. Public #293 integration `38cff412012567a5d0facc27ee5787b261d64417` independently returned `a-child` with an unrelated lonely seed's original similarity0.7 under a SearchScore-only program. Missing hop handling did not protect programs that did not request hops.

Additional bounded causes were confirmed on old main production: nullable column keys matched explicit NULL node properties in both fallback and indexed lookup; scalar WITH retained stale native target bindings and wrongly restricted a logically reintroduced variable to its previous node. The full required/optional reintroduction oracle expects four rows; the old normalized plan returned two. Projection intentionally retains canonical nodes for later execution/scoring, so physical map presence is insufficient evidence of logical scope.

Two initial aliased-YIELD reproductions failed parsing and are not behavior RED. The successful public scored reproductions use `YIELD id, score` and implicit canonical seed lookup.

## Repair and invariant

Represent a missing graph entity as an explicit `Value::Null` binding without a node/relationship record. Required traversal of NULL produces no match; OPTIONAL preserves upstream rows and only NULL extends new variables. Real NodeId0 remains a valid identity. Unknown OPTIONAL types consume upstream through the existing row-size, graph-budget, output-ledger, checkpoint and Stop callback. NULL lookup keys never reach storage comparison; unmatched optional lookup uses the same canonical representation.

The normalizer proves introduced node/relationship names absent from every native binding retained by its input before replacing generic MATCH with native Expand/column lookup. It follows projections and known inputs conservatively with a depth256 bound, and retains GraphMatch for unknown or overlapping shapes. Aggregate creates fresh value-only bindings in resident and spill paths, so its input cannot retain stale native entities. GraphMatch's existing introduced/import transitions handle reintroduction. Projection's canonical bindings and public struct layouts are preserved. The legacy public placeholder constructor remains available for source compatibility and is unused by internal nullable writers.

OptionalDegree handles a canonical NULL source as degree0. AdjacencyExists and its predicate independently return false when node bindings are absent. The degree guard is tested with actual nullable GraphMatch rows and a known relationship type, plus legitimate node0's one-hop degree as a control.

## Review found three reachable sibling defects

All three required SOURCE perspectives requested changes. Global OPTIONAL COUNT had a second GraphMatch-to-Expand rewrite that bypassed scope proofs and discarded unmatched rows even when counting a previously bound relationship. Native expansion constrained a bound target but overwrote a pre-bound relationship id. Unknown typed relationships returned before the valid zero-hop source result, in both native and generic execution.

Nine additional guards ran on the frozen partial production repair before these changes: eight API tests failed actual result assertions (forward/reverse reintroduction count2 versus4, bound relationship count4 versus2, unknown-type bound relationship count0 versus2, required zero-hop empty and optional zero-hop NULL versus the source); the independent native kernel returned4 rows versus2 for two real parallel relationships. Both Bazel targets failed, with unchanged source snapshots. This is a partial-candidate replay, not an execution of the pristine parent revision. Saved test source files and terminal assertion logs accompany the receipts so later additions cannot be mistaken for identical whole-file hashes.

The count rewrite now requires introduced-variable absence and exactly the target/relationship names a native expansion will create; a pre-bound count remains generic. Its native-input variant also proves the counted variable absent from upstream native bindings. Chained normalization shares the same introduced-set proof. Native matching filters by a pre-bound relationship's real id. The zero-hop path shares the original bounded traversal implementation, with an internal absent-type state that can emit depth0 and cannot enumerate wildcard edges. Public traversal spec and expansion signatures remain compatible. Generic GraphMatch uses the same zero-hop visitor and its existing target/scope transition. All new output still uses existing fit checks, ledger, graph budget, cancellation and Stop handling. Restored default-pipeline23/23 and kernel2/2 passed uncached, source1851 unchanged. The eight new API guard functions, fixture/count helper and native relationship guard match their RED source bytes exactly (eleven checked ranges). Complete refreshed qualification, mandatory fuzz, exact-head review and CI remain pending.

## Bound source label constraint

The final causal review found a separate existing constraint loss: native AdjacencyExpand ignored the label on an already-bound source. A source bound as Item incorrectly satisfied a following Other or unregistered Missing label, returning neighbors and nonzero OPTIONAL counts. Four public guards replayed the frozen pre-label repair and each failed an actual row/count assertion; the source snapshot stayed unchanged. Each guard covers both registered and unregistered labels and zero/one/two WITH projections. This is a partial-candidate RED, not a pristine-parent replay.

The native batch boundary now resolves and checks the source label before expansion. A mismatch uses the shared unmatched transition: required MATCH produces no row, while OPTIONAL retains upstream bindings and extends only introduced names with NULL. The ordinary accounted candidate callback still owns row/payload limits, graph budget, ledger release, cancellation and Stop. After this correction, the complete default-pipeline suite passed 27/27 and the kernel guards passed 2/2 uncached, with 1851 source files unchanged. The four label guard functions and fixture match their executed RED bytes; the earlier eleven guard/helper ranges also remain identical. Full final qualification, mandatory fuzz, commit/exact-head review and containing-source CI remain separate gates.
